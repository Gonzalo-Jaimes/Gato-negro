# Rol
Eres un diseñador-desarrollador front-end senior, especialista en accesibilidad (WCAG 2.1 AA) y en interfaces de uso industrial.

# Contexto
Aplicación web ERP «Gato Negro» para una fábrica artesanal de tabacos (Node.js + Express + vistas EJS, sin framework JS). La usan administradores en escritorio y operarios en celular dentro de la planta. Existe un sistema de diseño con variables CSS y clases ya definidas que DEBES reutilizar (no inventes otras):
- Espaciado: --space-1 … --space-12 (base 4 px). Texto: --text-sm, --text-base, --text-lg. Color: --primary, --danger, --success, --text-muted, --border-color, --bg-card.
- Clases: `.field` (contenedor de un campo), `.input` (input/select), `.field-hint` (ayuda), `.field-error` (mensaje de error), `.is-invalid` / `.is-valid` (estado del input), `.btn` + `.btn-success`, `.card`.
- Hay un helper global `UI.form(formEl, {campos: {nombre: (valor) => mensajeDeError | null}, enviar: async (datos) => ...})` que valida por campo, marca aria-invalid y muestra el error; úsalo si lo consideras adecuado, pero explica cómo.

# Tarea
Rediseñar el formulario de alta de empleados (HTML/EJS abajo) para que sea claro, usable en móvil y accesible.

# Restricciones (obligatorias)
1. No cambies los atributos `name` de los campos (`codigo`, `nombre`, `cedula`) ni el destino `action="/agregar_empleado"` con `method="POST"`.
2. No agregues librerías ni CDN nuevos.
3. Español neutro de Colombia en toda la interfaz.
4. No uses el `placeholder` como etiqueta: cada campo lleva `<label for>` visible.
5. Reglas de negocio: código = 1 a 3 letras + 1 a 4 números (ej. F01, AN12); nombre = 3 a 80 caracteres, solo letras, espacios, punto, apóstrofo o guion; documento = prefijo opcional (CC-, V-, E-) + 5 a 12 números.

# Criterios de aceptación
- Los 5 estados del campo: normal, foco, error, deshabilitado, éxito.
- Mensajes de error específicos (qué pasó y cómo corregirlo), nunca genéricos como «Campo inválido».
- Accesibilidad: `aria-invalid`, `aria-describedby` enlazado a la ayuda/error, foco al primer campo inválido, objetivos táctiles ≥ 44 px, sin depender solo del color.
- Responsive: 1 columna en móvil, varias en escritorio.

# Formato de salida
1. «Problemas detectados» en el original (lista numerada, máximo 8).
2. «Código final»: un único bloque con el HTML/EJS y el JavaScript necesarios.
3. «Verificación»: checklist de 6 comprobaciones que alguien pueda hacer en el navegador.
